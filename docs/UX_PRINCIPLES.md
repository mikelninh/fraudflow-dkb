# UX Principles — reviewer-first work sample

## Audience order

1. Recruiter / HR must understand the point in ~20 seconds.
2. Hiring manager must understand the workflow in ~60–90 seconds.
3. Engineer must be able to open technical details and reproduce the proof.

## Progressive disclosure

The default UI uses plain language. Technical identifiers, rule names, risk scores, API details and traceability metadata belong behind an explicit **Technical details** disclosure unless they are necessary to understand the decision.

## Five questions every screen should answer

1. What happened?
2. Why is it unusual?
3. What does the system recommend?
4. Who makes the final decision?
5. Where can I verify the claim?

## Visual direction

Use a calm blue/white banking aesthetic inspired by the target employer's public visual language without copying protected logos, trademarks or claiming affiliation. The work sample must clearly label itself as independent.

## Copy rule

Prefer:

- "5 payments in 27 seconds"
- "The last payment jumps to €499"
- "Recommendation: review"

Over:

- "transaction velocity"
- "amount anomaly"
- "65 risk points"
- "traceability chain"

The technical terms can still exist in the engineer layer.
